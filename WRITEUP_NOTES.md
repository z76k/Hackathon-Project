# AllerGuard AI: write-up notes and checklist

## Write-up sections (about 1 page, from the briefs)
- [ ] **Problem**
  - Same Dubai air, different risk: standard apps give everyone the same warning.
  - By the WHO daily PM2.5 guideline (15 µg/m³), JLT air was above the limit on 1,402 of 1,412 days (99%).
  - By the US EPA limit (35), it was above on 956 days (68%).
  - Caveat: these are model estimates (CAMS), which may run high for desert dust.
- [ ] **What we built**
  - A website with a health survey, then a personalised Apple Weather-style dashboard for JLT.
  - An ML forecast of tomorrow's PM2.5, plus personal limits and lower-risk hours.
  - Cloudy: AI-written advice, with fallbacks.
- [ ] **How it works**
  - Data: about 4 years of daily JLT air and weather (Open-Meteo), 2023-01-01 to 2026-11-12, saved in data/jlt_daily.csv.
  - Model: Random Forest (300 trees). Inputs: today's PM2.5, PM10, dust, temperature, humidity, max wind, rain, 7-day average, change since yesterday, month.
  - Split by date: trained on 2023–2025 (1,090 days), tested on 2026 (315 days).
  - Personal limits:
    - Sensitive group → 35.4 (EPA "Unhealthy for Sensitive Groups"). Applies to under 18, over 50, dust affects you, coughing, moderate or severe symptoms, or time outdoors.
    - Everyone else → 55.4 (EPA "Unhealthy").
    - Heat: 32°C feels-like if heat-sensitive (NWS "extreme caution"), otherwise 41°C (NWS "danger"). UV below 8 (WHO "very high").
  - Safety: severe symptoms → the app stops and points to medical help (998 in the UAE).
  - Architecture: Flask (Python) backend + HTML/JS frontend, connected by /api/analyze.
- [ ] **What we added** (the brief requires this section)
  - Personal limits from a survey, instead of one warning for everyone.
  - Lower-risk hours.
  - The safety check.
  - Mascot explanations.
  - An AI fallback chain.
  - A weather dashboard where every tile is compared with *your* limits.
- [ ] **Results** (compared with the baseline "tomorrow = today")
  - Average error (MAE): baseline 8.5, model 9.0 µg/m³. The model did NOT beat the baseline.
  - Sensitive warning (>35.4): baseline caught 239/262 bad days (23 missed, 23 false alarms); model caught 241/262 (21 missed, 19 false alarms).
  - Everyone warning (>55.4): baseline caught 104/134 (30 missed, 30 false alarms); model caught 88/134 (46 missed, 12 false alarms).
  - Tried v2 (Gradient Boosting predicting the change from today): MAE 9.1. No improvement.
  - Why: Dubai air changes slowly, so "tomorrow = today" is hard to beat. 2026 was much dirtier (134/315 days above 55, about 43%) than the training years (316/1,412 overall, about 22%).
  - App tests: 6 test profiles via test_api.py (teen + dust, healthy adult, older adult, outdoor runner, severe symptoms, empty answers). 6/6 passed.
- [ ] **Limitations**
  - Air data is a ~45 km global model grid (CAMS), not a JLT monitoring station.
  - The model misses more of the worst days than the baseline.
  - Free APIs fail: Gemma 4 timed out (504) on most requests during testing, and one Open-Meteo request dropped (SSL error). The app retries and falls back to Gemini 3.5 Flash-Lite, then Gemma 4 26B, then Gemma 4 31B, then a ready-written message.
  - Personal limits are simplified rules based on public guidance, not validated on patients.
  - Python + local server only. Judges run it with: `pip install -r requirements.txt && python app.py`.
- [ ] **What we'd do next**
  - A symptom diary to learn each person's own triggers (idea from the AllerGuard version).
  - Compare against real Dubai monitoring stations.
  - Dust-storm alerts.
  - More locations.
- [ ] **Disclaimer line:** "This project is a prototype and is not medical advice."
